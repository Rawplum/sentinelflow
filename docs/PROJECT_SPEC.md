# SentinelFlow 项目规格

## 1. 项目目标

SentinelFlow 帮助安全运营团队把分散的日志转化为可调查、可复核、可交付的安全事件结论。核心目标是：

1. 可靠地接入并归一化安全日志。
2. 使用确定性规则关联事件并生成告警。
3. 保留完整证据链，支持分析师复盘。
4. 生成结构化的调查报告和处置建议。
5. 为后续引入检索增强和 LLM Agent 提供受控、可审计的接口。

首期以**正确性、可测试性和安全边界**优先，不以功能数量或模型效果为优先。

## 2. 目标用户

| 用户 | 需求 |
| --- | --- |
| SOC 一线分析师 | 快速看到告警、关联事件和初步结论 |
| 事件响应工程师 | 追溯证据、记录调查过程、输出处置建议 |
| 安全负责人 | 审阅报告、确认风险等级和处置状态 |
| 平台/安全工程师 | 接入新日志源、维护规则、审计系统行为 |

已实现本地账户体系：`admin` / `analyst` 两种角色，Argon2id 密码哈希、JWT 访问令牌、后端强制 RBAC 和 append-only 审计。用户只能通过本地 CLI 创建，没有公开注册。上述用户画像仍用于界定功能范围，不代表已实现按团队或按资产的细粒度授权。

## 3. 主要使用场景

1. **日志接入**：通过 REST API 接收 JSON 格式的安全事件，校验后落库。
2. **规则检测**：用确定性规则（阈值、时间窗口、字段匹配）识别可疑行为。
3. **告警生成与关联**：规则命中后创建告警，并把相关事件关联到告警。
4. **调查研判**：查看告警、事件时间线和证据，记录状态变化。
5. **报告输出**：基于模板生成包含摘要、发现、时间线、风险和建议的报告。
6. **审计追踪**：记录谁在何时执行了何种敏感操作（后续阶段）。
7. **AI 辅助（后续）**：在受控工具集内检索证据、总结事件，输出需人工复核的结论。

## 4. 首期功能范围

首期（Phase 1）计划包含：

- 核心实体：`SecurityEvent`、`Alert`、`InvestigationReport`。
- 事件接入 API：单条和批量 JSON 事件，幂等/去重。
- 确定性规则引擎：配置化规则、时间窗口、阈值、字段条件，不调用 LLM。
- 告警生命周期：创建、确认、调查中、关闭，保留状态变更记录。
- 事件与告警关联、证据查询。
- 基于模板的确定性调查报告。
- 基础审计记录、输入校验和资源限制。
- 最小权限模型：角色划分和接口级授权。

**Phase 1 不包含**任何 LLM 调用，也不包含自动化的网络扫描、主机隔离或阻断操作。

## 5. 非目标

以下内容明确不在当前阶段：

- 接入任何大模型或外部 AI 服务。
- 多 Agent 协作、自主规划和自动处置。
- 真实网络扫描、漏洞利用、主机控制、防火墙联动。
- 微服务、Kubernetes、消息队列、分布式任务调度。
- 面向多租户的 SaaS 能力。
- 生产级单点登录、MFA、细粒度 ABAC。
- 对真实生产日志的采集代理和长期数据湖。

## 7. 约束与假设

- 单机、单进程的模块化单体优先。
- 同步 SQLAlchemy，数据库为 PostgreSQL。
- 本地开发通过 `uvicorn` + Docker Compose 中的 PostgreSQL 运行。
- 所有时间使用 UTC 存储，API 使用 ISO 8601。
- 所有测试数据必须是合成的，不包含真实日志、个人信息或凭据。
- 在认证授权完成前，服务只能绑定回环地址。

## 8. 成功度量（计划）

- 规则告警的误报率可被量化并持续下降。
- 单次事件接入的 P95 延迟在本地基线下可测量。
- 报告中的每个结论都能追溯到具体事件 ID。
- 所有敏感写操作可审计。
- 后续 Agent 输出的每条关键结论都能引用证据。
