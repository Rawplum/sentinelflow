### 5.2 未受保护的接口

OpenAPI 里共 20 个操作，其中**只有 3 个不需要认证**：

```
GET  /health          存活探针（不碰数据库）
GET  /health/ready    就绪探针（含数据库往返，失败 503，不回显连接串）
POST /api/v1/auth/login
```

其余 17 个全部要求 `Authorization: Bearer`，且按角色校验权限。
`/api/v1/users` 不存在（返回 404）——用户管理只能通过 CLI 或服务层，没有远程管理面。

## 6. 已知限制

### 6.1 安全

1. **没有 TLS**。默认只绑 `127.0.0.1`；对外提供服务前必须加反向代理和证书。
2. **没有 MFA、没有刷新令牌、没有密钥轮换**。
3. **`/docs`、`/redoc`、`/openapi.json` 公开**。这是本地演示的便利，也是信息暴露面；
   对外部署时应关闭或加访问控制。
4. **审计没有保留策略**，只增不删，长期运行需要归档方案。
5. **限流是数据库实现的**，多副本共享同一数据库时有效，但每个请求多一次写。

### 6.2 能力边界

1. 只做认证日志的暴力破解检测（`AUTH-001`），没有扫描、阻断、自动响应。
2. Agent 只产出**草稿**报告，定稿必须由管理员手动操作。
3. 工具超时用线程池实现，超时后工作线程不会被强制终止。
4. 单进程单 worker；**多副本 worker 并发未验证**。

### 6.3 质量证据的强度

1. **评测集只有 22 个可评用例**，期望由作者一人设定，rubric 改过两版。
   93% 衡量的是"与作者判断一致的程度"，不是客观正确率。
2. **真实模型只测过一个**（DeepSeek-V4.1-Flash），不能外推。
3. **两次运行 5 处判定翻转**——任何单次结果都只是抽样。

## 8. 本轮修复记录

### 8.1 README「已知限制」整段过期（高）

原文声称："Agent 只用 Mock 模型验证过"、"没有固定评测集"、"Agent 同步执行，没有后台任务队列"、
"Docker Compose 未验证"、"Git 仓库已初始化但没有任何提交"。

实际情况：有真实模型评测、有 25 个用例的评测集、有数据库任务队列、
容器化已移除、有 15 个提交。

这些不是小错——一个评审者读完会得到完全相反的结论。已按实际情况重写。

### 8.2 `docs/SECURITY.md` 测试数字过期（中）

`318 passed, 1 skipped` → 更正为 `362 passed, 3 skipped`，并补上三个安全测试文件的分别计数。

### 8.3 `scripts/` 不在检查范围内（中）

`scripts/check.py` 的 `PYTHON_TARGETS` 没有包含 `scripts`，mypy 的 `files` 也没有。
结果是**检查脚本自己不被检查**。纳入后发现 5 处格式问题、2 处类型问题（`perf/harness.py`
的 `stderr` 可能为 `None`、f-string 里嵌 bytes），已修。

### 8.4 顺带

- `benchmark/` 缺 `__init__.py`，导致 mypy 把 `benchmark/dataset.py` 当成两个模块。
  补上包标记后 mypy 覆盖到 107 个文件。
- `docs/DECISIONS.md` 开头加了阅读提示：早期条目里的 Docker 建议已被 D-050 取代。

**没有做的事**：没有为了通过验收而禁用任何检查、删除任何测试或放宽任何断言。
本轮唯一的"降低标准"是把 `scripts/` 纳入检查后**修代码**，不是加豁免。

## 9. 复核方法

```bat
:: 1. 干净环境
py -3.11 -m venv .venv && .venv\Scripts\activate
python -m pip install -e ".[dev]"

:: 2. 静态检查 + 单元测试
python scripts/check.py

:: 3. 空库迁移（需要 PostgreSQL 16）
createdb sentinelflow
set DATABASE_URL=postgresql+psycopg://user:pass@127.0.0.1:5432/sentinelflow
set JWT_SECRET=<至少 32 字符>
sentinelflow-doctor
alembic upgrade head
alembic check

:: 4. 端到端验收（自建服务、自建桩模型、自动重置数据库）
set PERF_DATABASE_BASE=postgresql+psycopg://user:pass@127.0.0.1:5432
python scripts/acceptance.py --database sentinelflow --reset

:: 5. 前端
cd frontend && npm install && npm test && npm run lint && npm run build

:: 6. 浏览器端到端（需要 API 与 vite 同时在跑）
node e2e/browser.mjs
```

第 4 步会 **DROP 并重建** 指定数据库，只用于专用验收库。
